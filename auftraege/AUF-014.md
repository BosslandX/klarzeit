# AUF-014 — Übertragung an Clockodo vorbereiten

## Auftrag

Aus einem Eintrag entstehen rein rechnerisch die Clockodo-Einträge, die übertragen würden (je
Arbeitsabschnitt zwischen den Pausen einer), samt Übertragungsstatus und Prüfsumme; der Client
kann Clockodo-Einträge anlegen und löschen; der Übertragungsstand eines Eintrags reist durchs
Backup. **Noch kein Ablauf, kein Knopf** — das ist AUF-015.

## Warum das gebraucht wird

Der User will Einträge an Clockodo übertragen (nur Klarzeit → Clockodo). Clockodo kennt kein
Pausenfeld; ein Eintrag mit Pausen wird zu mehreren Clockodo-Einträgen (seit AUF-011 kennt
Klarzeit die Pausenzeiten). Damit ein zweiter Lauf nichts doppelt sendet und eine Änderung
erkannt wird, merkt sich jeder Eintrag die IDs der angelegten Clockodo-Einträge und eine
Prüfsumme des Gesendeten.

## Primärquelle

`https://docs.clockodo.com/openapi.yaml` (info.version 2026-09-23), wörtlich geprüft:
- `POST /v2/entries`, Zeiteintrag: `required: ['customers_id', 'time_since', 'time_until',
  'services_id']`; optional `projects_id` (integer|null), `billable` (0|1), `text` (string|null).
  `time_since`/`time_until`: `format: date-time`, Beispiel `2023-02-28T12:00:00Z`.
  Antwort 200: `{ entry: EntryV2, stopped }`, `EntryV2` trägt `id`. Weitere Codes 400, 401, 403,
  404, 409.
- `DELETE /v2/entries/{id}` → 200 `{ success: true }`; 400.

### 2 — Rein: `src/domain/clockodo-transfer.ts`

```ts
export interface ClockodoEntryPayload {
  customers_id: number;
  services_id: number;
  projects_id?: number;
  billable?: 0 | 1;
  time_since: string;
  time_until: string;
  text?: string;
}
export type TransferStatus =
  | 'none' | 'before-start' | 'untimed-break' | 'incomplete' | 'pending' | 'changed' | 'synced';
export function workSegments(entry: Pick<TimeEntry, 'start' | 'end' | 'breaks'>): { start: number; end: number }[];
export function toClockodoTime(ms: number): string;
export function entryText(entry: Pick<TimeEntry, 'activity' | 'note'>): string | null;
export function buildEntryPayloads(entry: Pick<TimeEntry, 'start' | 'end' | 'breaks' | 'activity' | 'note'>, ref: ClockodoEntryRef, billable: 0 | 1 | null): ClockodoEntryPayload[];
export function entrySyncHash(entry: Pick<TimeEntry, 'start' | 'end' | 'breaks' | 'activity' | 'note'>, ref: ClockodoEntryRef, billable: 0 | 1 | null): string;
export function transferStatus(entry: TimeEntry, config: ClockodoConfig | null): TransferStatus;
```

- `workSegments`: `[start, end]` minus die nach Beginn sortierten Pausen (Eingabe nicht
  verändern); Pausen werden auf den Eintrag begrenzt; Abschnitte der Länge 0 fallen weg. Ohne
  Pausen genau ein Abschnitt.
- `toClockodoTime`: UTC ohne Millisekunden, z. B. `2026-07-06T06:00:00Z`
  (`toISOString()` mit entfernten Millisekunden).
- `entryText`: `activity` und `note`, je getrimmt, leere weg, verbunden mit `' – '`; beide leer →
  `null`.
- `buildEntryPayloads`: je Abschnitt `{ customers_id, services_id, time_since, time_until }`;
  `projects_id` **nur** wenn `ref.projectsId !== null`, `billable` nur wenn `billable !== null`,
  `text` nur wenn `entryText` nicht `null` ist.
- `entrySyncHash`: FNV-1a 32 Bit als 8-stellige Kleinbuchstaben-Hex über
  `JSON.stringify(buildEntryPayloads(entry, ref, billable))` — ändert sich genau dann, wenn sich
  das Gesendete ändert; `id`, `updatedAt`, `createdAt`, `clockodoSync` gehen nicht ein.
- `transferStatus` — **erste zutreffende Regel gewinnt, in dieser Reihenfolge:**
  `config === null` → `'none'`; `entry.start < config.syncFrom` → `'before-start'`;
  `entry.breakMinutes > 0` ohne `breaks` (fehlt oder leer) → `'untimed-break'`; kein
  `entry.clockodo` → `'incomplete'`; kein `entry.clockodoSync` → `'pending'`;
  `entry.clockodoSync.hash !== entrySyncHash(entry, entry.clockodo, config.billable)` →
  `'changed'`; sonst `'synced'`.

### 3 — Übertragungsstand, Backup, Client

- `src/domain/clockodo.ts`: `ClockodoSync { ids: number[]; hash: string; at: number }` und rein
  `cleanClockodoSync(raw): ClockodoSync | null` — `ids` nicht leeres Array, **jedes** Element
  positive Ganzzahl (`positiveInt`); `hash` nicht leerer Text; `at` endliche Zahl; sonst `null`.
- `src/domain/types.ts`: `TimeEntry.clockodoSync?: ClockodoSync` (fehlt = nie übertragen).
  **`EntryDraft` bekommt es nicht**: das Formular ändert den Stand nie, und `updateEntry`
  (Dexie-`update`) lässt ihn stehen — so bleibt ein bearbeiteter Eintrag als `'changed'` erkennbar.
- `src/db/backup.ts` `cleanEntry`: `clockodoSync` über `cleanClockodoSync`, ungültig/fehlend →
  Feld fehlt. Grund: ein zurückgespieltes Backup darf nichts ein zweites Mal senden.
- `src/clockodo/client.ts`:
  - `ClockodoRequest.method` wird `'GET' | 'POST' | 'DELETE'`, dazu `data?: unknown`; der
    Standard-HTTP reicht `data` an `CapacitorHttp.request` weiter. Die GET-Wege aus AUF-012
    bleiben im Verhalten gleich (ihre Tests unverändert grün). `clockodoHeaders` bleibt, wie es
    ist.
  - `createEntry(auth, payload, http?) → Promise<number>`: `POST ${CLOCKODO_API}/v2/entries`,
    Header `{ ...clockodoHeaders(auth), 'Content-Type': 'application/json' }`, `data: payload`;
    Status wie bisher über dieselbe Fehlerabbildung; Ergebnis `entry.id` (positive Ganzzahl),
    sonst `ClockodoError('format', …)`.
  - `deleteClockodoEntry(auth, id, http?) → Promise<void>`: `DELETE ${CLOCKODO_API}/v2/entries/<id>`;
    2xx **und 404** gelten als Erfolg (schon weg); alles andere über die Fehlerabbildung.
