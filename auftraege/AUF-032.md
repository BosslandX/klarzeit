# AUF-032 — Vertrag gültig ab im Formular; App-Update als eigene Komponente

## Auftrag

Ändert man im Formular einer Beschäftigung die Wochenstunden oder die Arbeitstage, fragt das Formular,
ab wann die Änderung gilt (vorbelegt: der 1. des laufenden Monats) — oder ob sie eine Korrektur von
Beginn an ist. Beim Speichern wird der bisherige Vertrag ein früherer Stand bis zum Vortag
(`contractHistory` aus AUF-031). Die früheren Stände stehen darunter und lassen sich entfernen. Dazu
wandert der Abschnitt „App-Update" unverändert aus `MoreScreen.tsx` in eine eigene Komponente.

## Warum das gebraucht wird

AUF-031 hat die Rechnung geliefert, aber nichts füllt `contractHistory`: Eine geänderte Stundenzahl
rechnet weiter alle Vormonate neu. **Entscheidung des Nutzers (2026-11-17):** „Vertrag gültig ab" früh
einplanen — dies ist der zweite Teil.

Zwei Umbauten haben gemessene Gründe: `MoreScreen.tsx` hat 797 Zeilen, die Grenze des Projekts
liegt bei 800 — deshalb zieht der Update-Abschnitt aus. Die vier neuen Funktionen stehen in einem eigenen
Modul `src/domain/contract-change.ts`, weil `employment.ts` mit ihnen 807 Zeilen hätte.

**Festgelegt (vom Auftraggeber, nicht ändern):**

- Keine Änderung sind das erste Eintragen (bisher 0 Wochenstunden) und das **erstmalige Wählen der
  Wochentage bei gleicher Zahl** — das ist eine Angabe zum bestehenden Vertrag. Ohne diese Ausnahme legte
  schon die Wahl der Wochentage einen früheren Stand nach der alten Regel (Montag bis Freitag) an, und ein
  Urlaubszeitraum vor dem Stichtag zählte wieder fünf statt vier Tage (an der Referenz gemessen).
- „Gilt ab" muss nach dem Beginn der Beschäftigung und nach dem Beginn des laufenden Vertrags liegen;
  sonst meldet das Formular das und speichert nichts.
- Eine Korrektur („gilt von Beginn an") lässt die früheren Stände, wie sie sind.

## Was zu tun ist

### 0 — Drei getrennte Einspiel-Läufe, in dieser Reihenfolge

**Erst wenn ein Schritt gemessen ist, wird das Skript des nächsten geschrieben.** Die Zeitstempel werden
nachgesehen, Abweichungen gehören in `nicht_erreicht`.

1. `auftraege/_probe/AUF-032_teil1.py` spielt das **Gerüst** (Schritt 1) ein → `npx tsc --noEmit` und
   `npx vitest run`, Ausgabe nach `auftraege/_ergebnisse/AUF-032_geruestlauf.txt`.
2. `auftraege/_probe/AUF-032_teil2.py` spielt die **Tests** (Schritt 2) ein → `npx tsc --noEmit` und
   `npx vitest run`, die **vollständige, wörtliche** Ausgabe von vitest (stdout und stderr, als UTF-8)
   **sofort** nach `auftraege/_ergebnisse/AUF-032_ausgangslauf.txt` — **kein Auszug**. Diese Datei danach
   **nie wieder schreiben**.
3. Erst dann `auftraege/_probe/AUF-032_teil3.py` mit der **Umsetzung** (Schritt 3).

**Jedes Suchstück kommt in seiner Datei genau einmal vor**; das Skript prüft das und bricht sonst ab,
ohne zu schreiben. Mehrere Stücke derselben Datei werden in der angegebenen Reihenfolge nacheinander
angewandt; zwei Stücke werden **ersatzlos gelöscht**. Die vorhandenen Dateien stehen im Arbeitsort mit
**CRLF**: Suchstück und Ersatz mit `\r\n` anwenden, Zeilenenden wie vorgefunden lassen; die neuen
Dateien mit LF, und jede endet mit einem Zeilenumbruch (in AUF-031 fehlte er zweimal am Dateiende).
Dateien als **Bytes** lesen und schreiben — `write_text(newline='\r\n')` auf Text, der schon `\r\n`
trägt, ergibt `\r\r\n` (so geschehen in AUF-031). Codierung UTF-8; die Stücke des Update-Abschnitts
enthalten `…` (U+2026) und `–` (U+2013), die genau so bleiben.

Unter Windows ist `npx` eine `.cmd`-Datei: im Hilfsskript `npx.cmd` aufrufen oder `shell=True` setzen (in
AUF-031 scheiterte der erste Lauf daran).

**Negativkontrollen nur an einer Kopie**, nie am Arbeitsstand: `src/`, `package.json`,
`vite.config.ts` und `tsconfig.json` nach `auftraege/_probe/AUF-032_nk/` kopieren und dort mutieren und
messen (`npx vitest run` mit diesem Ordner als Arbeitsverzeichnis). Die NK-Ergebnisdatei schreibt das
NK-Skript **vor** der Lieferung; danach weder die Lieferung noch die Ergebnisdatei neu schreiben.

export function contractChanged(saved: ContractTerms, next: ContractTerms): boolean {
  if (saved.weeklyHours <= 0) return false;
  if (saved.weeklyHours !== next.weeklyHours || saved.workdaysPerWeek !== next.workdaysPerWeek) {
    return true;
  }
  // Wochentage erstmals gewaehlt (bisher nur ihre Zahl): eine Angabe, keine Vertragsaenderung.
  if (saved.workWeekdays === undefined) return false;
  return saved.workWeekdays.join(',') !== (next.workWeekdays ?? []).join(',');
}

export function describeContract(terms: ContractTerms): string {
  const kurz = ['So', 'Mo', 'Di', 'Mi', 'Do', 'Fr', 'Sa'];
  const stunden = String(terms.weeklyHours).replace('.', ',');
  const tage =
    terms.workWeekdays && terms.workWeekdays.length > 0
      ? [...terms.workWeekdays]
          .sort((a, b) => ((a + 6) % 7) - ((b + 6) % 7))
          .map((t) => kurz[t])
          .join(' ')
      : `${terms.workdaysPerWeek} Arbeitstage`;
  return `${stunden} Std./Woche, ${tage}`;
}

import { useState } from 'react';
import { checkForUpdate, downloadAndInstall, type UpdateInfo } from '../../update/updater';

/** App-Update: nach einer neueren Version suchen und sie installieren (aus MoreScreen ausgelagert). */
export function UpdateSection() {
  const [updateBusy, setUpdateBusy] = useState(false);
  const [updateMsg, setUpdateMsg] = useState('');
  const [available, setAvailable] = useState<UpdateInfo | null>(null);

  const onCheckUpdate = async () => {
    setUpdateBusy(true);
    setUpdateMsg('');
    setAvailable(null);
    try {
      const info = await checkForUpdate();
      if (info) {
        setAvailable(info);
        setUpdateMsg(
          `Neue Version ${info.versionName} verfuegbar (installiert: ${info.currentVersionName}).`,
        );
      } else {
        setUpdateMsg('Du hast bereits die neueste Version.');
      }
    } catch (e) {
      setUpdateMsg(`Update-Pruefung fehlgeschlagen: ${msg(e)}`);
    } finally {
      setUpdateBusy(false);
    }
  };

  const onInstallUpdate = async () => {
    if (!available) return;
    setUpdateBusy(true);
    setUpdateMsg('Lade Update herunter …');
    try {
      await downloadAndInstall(available);
      setUpdateMsg('Installation gestartet – bitte den System-Dialog bestaetigen.');
    } catch (e) {
      setUpdateMsg(`Update fehlgeschlagen: ${msg(e)}`);
    } finally {
      setUpdateBusy(false);
    }
  };

  return (
    <section className="card-section">
      <h2>App-Update</h2>
      <p className="muted small">
        Sucht auf dem Server nach einer neueren Version und installiert sie.
      </p>
      <button className="btn" onClick={onCheckUpdate} disabled={updateBusy}>
        Nach Update suchen
      </button>
      {available && (
        <button
          className="btn btn-primary"
          onClick={onInstallUpdate}
          disabled={updateBusy}
        >
          Update {available.versionName} installieren
        </button>
      )}
      {updateMsg && <p className="muted small">{updateMsg}</p>}
      {available?.notes && <p className="muted small">{available.notes}</p>}
    </section>
  );
}

```tsx
import { startOfMonth } from 'date-fns';
import {
  contractChanged,
  describeContract,
  removeContractPeriod,
} from '../../domain/contract-change';
import type { Employment } from '../../domain/employment';
import { formatDate, fromDateInput, toDateInput } from '../../domain/time';

/**
 * Vertrag gueltig ab (AUF-032): Aendern sich Wochenstunden oder Arbeitstage, fragt das Formular,
 * ab wann die Aenderung gilt -- oder ob sie eine Korrektur von Beginn an ist. Darunter die
 * frueheren Vertragsstaende zum Entfernen.
 */
export function ContractChangeField({
  saved,
  draft,
  ab,
  onAb,
  onDraft,
}: {
  saved: Employment | undefined;
  draft: Employment;
  ab: number | null;
  onAb: (next: number | null) => void;
  onDraft: (next: Employment) => void;
}) {
  const geaendert = saved !== undefined && contractChanged(saved, draft);
  const historie = draft.contractHistory ?? [];
  if (!geaendert && historie.length === 0) return null;
  return (
    <>
      {geaendert && (
        <>
          <p className="muted small">Wochenstunden oder Arbeitstage geaendert. Ab wann gilt das?</p>
          <label className="field">
            <span>Gilt ab</span>
            <input
              type="date"
              value={ab === null ? '' : toDateInput(ab)}
              disabled={ab === null}
              onChange={(e) => {
                const t = fromDateInput(e.target.value);
                if (!Number.isNaN(t)) onAb(t);
              }}
            />
          </label>
          <label className="field row">
            <span>Korrektur: gilt von Beginn an</span>
            <input
              type="checkbox"
              checked={ab === null}
              onChange={(e) => onAb(e.target.checked ? null : startOfMonth(Date.now()).getTime())}
            />
          </label>
        </>
      )}
      {historie.length > 0 && (
        <>
          <p className="muted small">Fruehere Vertragsstaende</p>
          <ul className="vac-list">
            {historie.map((c) => (
              <li key={c.validUntil}>
                <span>
                  bis {formatDate(c.validUntil)}: {describeContract(c)}
                </span>
                <button
                  className="link-btn danger"
                  type="button"
                  onClick={() =>
                    onDraft({
                      ...draft,
                      contractHistory: removeContractPeriod(draft.contractHistory, c.validUntil),
                    })
                  }
                >
                  entfernen
                </button>
              </li>
            ))}
          </ul>
        </>
      )}
    </>
  );
}
```
