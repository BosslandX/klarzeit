# AUF-033 — Krankheit: Zeiträume, Konto, § 9 BUrlG, Backup (ohne Oberfläche)

## Auftrag

Eine Beschäftigung trägt Krankheitszeiträume (von–bis in Kalendertagen, mit dem Vermerk, ob eine
ärztliche Bescheinigung vorliegt), gespeichert in Preferences unter `sickPeriods` und im Backup. Das
Arbeitszeitkonto schreibt Krankheitstage an eigenen Arbeitstagen bis zum Tagessoll gut, wie Urlaub und
Feiertage. Ein Urlaubstag in einem bescheinigten Zeitraum zählt nicht als Urlaub. Eine Beschäftigung mit
Krankheitszeiten lässt sich nicht löschen. Die Oberfläche folgt im nächsten Auftrag.

## Warum das gebraucht wird

Bisher erzeugt Krankheit Minusstunden (CLAUDE.md, „Nicht abgebildet"). Krankheit ist Punkt 3 des mit dem
Nutzer abgestimmten Plans.

**Rechtsgrundlagen, am 2026-11-17 wörtlich an gesetze-im-internet.de geprüft:**

- § 3 Abs. 1 Satz 1 EntgFG: Anspruch auf Entgeltfortzahlung „für die Zeit der Arbeitsunfähigkeit bis zur
  Dauer von sechs Wochen".
- § 4 Abs. 1 EntgFG: fortzuzahlen ist das Arbeitsentgelt, das „bei der für ihn maßgebenden regelmäßigen
  Arbeitszeit" zusteht — daher füllt ein Krankheitstag bis zum Tagessoll auf.
- § 9 BUrlG: „die durch ärztliches Zeugnis nachgewiesenen Tage der Arbeitsunfähigkeit" werden auf den
  Jahresurlaub nicht angerechnet — daher der Vermerk `certificate`.

**Festgelegt (vom Auftraggeber, nicht ändern):**

- Ein Zeitraum zählt Kalendertage einschließlich Wochenende. Gutgeschrieben wird nur an eigenen
  Arbeitstagen; ein Feiertag zählt als Feiertag.
- Ein Urlaubstag in einem Zeitraum **mit** Bescheinigung ist ein Krankheitstag und kein Urlaub; **ohne**
  Bescheinigung bleibt er Urlaub und ist kein Krankheitstag (`splitVacationAndSickness`). Auch wenn ein
  Aufrufer ungetrennte Listen gibt, zählt kein Tag doppelt.
- Urlaub, Feiertage und Krankheit zusammen höchstens das Monats-Soll.
- Die Gutschrift endet nicht nach sechs Wochen; `longSickRuns` liefert die Grundlage für einen Hinweis
  in der Oberfläche. Die vierwöchige Wartezeit (§ 3 Abs. 3 EntgFG) bildet die App nicht ab — das Konto
  rechnet Stunden, nicht Entgelt.
- Überschneidende Zeiträume derselben Beschäftigung: Eintragen wird abgewiesen, beim Bereinigen und
  Zusammenführen bleibt der frühere beziehungsweise der lokale.
- Die Gutschrift „bis zum Tagessoll, abzüglich erfasster Zeit" steht künftig an einer Stelle
  (`fillUpCreditMs`), die Urlaub und Feiertage mitbenutzen; eine dritte Kopie brächte `employment.ts`
  über 800 Zeilen. Deren Verhalten bleibt gleich, die bestehenden Tests halten das fest.

## Was zu tun ist

### 0 — Drei getrennte Einspiel-Läufe, in dieser Reihenfolge

**Erst wenn ein Schritt gemessen ist, wird das Skript des nächsten geschrieben.** Die Zeitstempel werden
nachgesehen, Abweichungen gehören in `nicht_erreicht`.

1. `auftraege/_probe/AUF-033_teil1.py` spielt das **Gerüst** (Schritt 1) ein → `npx tsc --noEmit` und
   `npx vitest run`, Ausgabe nach `auftraege/_ergebnisse/AUF-033_geruestlauf.txt`.
2. `auftraege/_probe/AUF-033_teil2.py` spielt die **Tests** (Schritt 2) ein → `npx tsc --noEmit` und
   `npx vitest run`, die **vollständige, wörtliche** Ausgabe von vitest (stdout und stderr, als UTF-8)
   **sofort** nach `auftraege/_ergebnisse/AUF-033_ausgangslauf.txt` — **kein Auszug**. Diese Datei danach
   **nie wieder schreiben**.
3. Erst dann `auftraege/_probe/AUF-033_teil3.py` mit der **Umsetzung** (Schritt 3).

**Jedes Suchstück kommt schon in der Ausgangsdatei seines Schritts genau einmal vor** (vom Auftraggeber
so geprüft); das Skript prüft das und bricht sonst ab, ohne zu schreiben. Mehrere Stücke derselben Datei
werden in der angegebenen Reihenfolge nacheinander angewandt.

**Zeilenenden — in AUF-032 trotz Hinweis wieder schiefgegangen** (drei Importzeilen mit `\r\r\n`): Die
vorhandenen Dateien stehen im Arbeitsort mit **CRLF**, die Stücke dieses Auftrags mit LF. Dateien als
**Bytes** lesen und schreiben; Suchstück und Ersatz **genau einmal** von `\n` nach `\r\n` umwandeln,
und zwar den LF-Text aus dem Auftrag — nie einen Text, der schon `\r` enthält. Vor dem Schreiben prüfen,
dass die Datei kein `\r\r` enthält. Die neuen Dateien mit LF, jede endet mit einem Zeilenumbruch.
Codierung UTF-8; die Stücke enthalten `§` (U+00A7), das genau so bleibt.

Unter Windows sind `npx` und `npm` `.cmd`-Dateien: im Hilfsskript `npx.cmd`/`npm.cmd` aufrufen oder
`shell=True` setzen (in AUF-031 und AUF-032 scheiterte je ein Lauf daran).

**Negativkontrollen nur an einer Kopie**, nie am Arbeitsstand: `src/`, `package.json`,
`vite.config.ts` und `tsconfig.json` nach `auftraege/_probe/AUF-033_nk/` kopieren und dort mutieren und
messen (`npx vitest run` mit diesem Ordner als Arbeitsverzeichnis). Die NK-Ergebnisdatei schreibt das
NK-Skript **vor** der Lieferung; danach weder die Lieferung noch die Ergebnisdatei neu schreiben.

  });

    expect(buildVacationStatus(vollzeit, mit.vacationDates, 2026).taken).toBe(3);
    const ohne = splitVacationAndSickness(urlaub, [p(d(2026, 6, 10), d(2026, 6, 11), false)], 'emp-1');
    expect(buildVacationStatus(vollzeit, ohne.vacationDates, 2026).taken).toBe(5);
  });

export function cleanSickPeriods(raw: unknown): SickPeriod[] {
  if (!Array.isArray(raw)) return [];
  const kandidaten: SickPeriod[] = [];
  for (const item of raw) {
    if (typeof item !== 'object' || item === null) continue;
    const x = item as Record<string, unknown>;
    if (typeof x.employmentId !== 'string' || x.employmentId === '') continue;
    if (typeof x.from !== 'number' || !Number.isFinite(x.from)) continue;
    if (typeof x.to !== 'number' || !Number.isFinite(x.to)) continue;
    const from = startOfDay(x.from).getTime();
    const to = startOfDay(x.to).getTime();
    if (to < from) continue;
    kandidaten.push({ employmentId: x.employmentId, from, to, certificate: x.certificate === true });
  }
  return [...kandidaten]
    .sort((a, b) => a.from - b.from || a.to - b.to)
    .reduce<SickPeriod[]>(
      (out, p) => (out.some((q) => sickPeriodsOverlap(q, p)) ? out : [...out, p]),
      [],
    );
}

/**
 * Krankheitstage eines Monats an eigenen Arbeitstagen und die Gutschrift dafuer (AUF-033): bis
 * zum Tagessoll, abzueglich am Tag erfasster Zeit -- fortgezahlt wird das Entgelt der
 * massgebenden regelmaessigen Arbeitszeit (§ 4 Abs. 1 EntgFG). Ein Feiertag zaehlt als Feiertag,
 * ein Urlaubstag als Urlaub; welche Urlaubstage krank zaehlen, entscheidet vorher
 * splitVacationAndSickness (§ 9 BUrlG). Die App rechnet Krankheitstage auch nach sechs Wochen
 * nicht als Minusstunden; dass die Entgeltfortzahlung endet, meldet longSickRuns.
 */
function sickOfMonth(
  emp: Employment,
  entries: readonly TimeEntry[],
  sickDates: readonly number[],
  vacationDates: readonly number[],
  monthRef: number,
): { days: number; creditMs: number } {
  const mStart = startOfMonth(monthRef).getTime();
  const mEnd = endOfMonth(monthRef).getTime();
  const empStart = startOfDay(emp.startDate).getTime();
  const empEnd = emp.endDate != null ? endOfDay(emp.endDate).getTime() : Infinity;
  const jahr = getYear(monthRef);
  const feiertage = publicHolidayMap(emp.publicHolidays, jahr, jahr);
  const urlaub = new Set(vacationDates.map((d) => startOfDay(d).getTime()));
  const tage = sickDates.filter((d) => {
    const tag = startOfDay(d).getTime();
    return (
      d >= mStart &&
      d <= mEnd &&
      d >= empStart &&
      d <= empEnd &&
      wochentageAm(emp, d).includes(getDay(d)) &&
      !feiertage.has(tag) &&
      !urlaub.has(tag)
    );
  });
  return { days: tage.length, creditMs: fillUpCreditMs(emp, entries, tage) };
}
