# AUF-043 — `MoreScreen.tsx` aufteilen, ohne dass sich etwas ändert

## Auftrag

`src/ui/screens/MoreScreen.tsx` (770 Zeilen) wird in vier Komponenten aufgeteilt: `ProfileSection`
(Persönliche Daten), `EmploymentEditForm` (Formular „Beschaeftigung bearbeiten“), `VacationSection`
(Genommene Urlaubstage) und `BackupSection` (Daten-Backup). Der Bildschirm „Mehr“ verhält sich danach genau
wie vorher; `MoreScreen.tsx` hat 229 Zeilen.

## Warum das gebraucht wird

Plan-Punkt 6. `MoreScreen.tsx` steht bei 770 Zeilen, die Projektregeln setzen 800 als Obergrenze — die
nächste Änderung an „Mehr“ ginge darüber. Aus demselben Grund wurde mit AUF-032 schon `UpdateSection`
ausgelagert.

**Festgelegt (vom Auftraggeber, nicht ändern):**

- Bewegter Code bleibt **wörtlich**, mit denselben Namen; nur die Einrückung ändert sich. Genau drei
  Ausnahmen, alle im Formular: `const emp = editDraft;` statt `editDraft ?? vacEmp` (im Formular ist der
  Entwurf immer gesetzt); aus demselben Grund entfallen die Bedingung `editingId && editDraft &&` vor
  `ClockodoSettings` und die Prüfungen `if (!editDraft) return;`; die drei Knöpfe rufen `onSave`,
  `onDelete` und `onCancel`.
- **In `MoreScreen` bleiben** der Entwurf (`editingId`, `editDraft`), „Gilt ab“ (`aenderungAb`), die
  Anzeige „Gespeichert“ der Beschäftigung (`empFlash`), die Auswahl „Urlaub fuer Beschaeftigung“
  (`vacEmpId`) und alle Hooks: Jedes Öffnen des Formulars setzt „Gilt ab“ zurück, „Gespeichert“ steht noch
  da, wenn das Formular kurz nach dem Speichern wieder geöffnet wird, an der Auswahl hängen Urlaub und
  Krankheitszeiten, und die Ladesperre „Lade…“ wartet auf die Hooks.
- In die neuen Komponenten wandert nur Zustand, der allein ihnen gehört: Profilformular samt seinem
  „Gespeichert“, `busy` und Dateiauswahl des Backups, die vier Eingaben des Urlaubsbereichs.

## Was zu tun ist

### 0 — Zwei getrennte Einspiel-Läufe, in dieser Reihenfolge, jeder genau einmal

**Erst wenn ein Schritt gemessen ist, wird das Skript des nächsten geschrieben** — auch keine Dateien
für einen späteren Schritt vorher anlegen, **auch kein NK-Skript**. Die Zeitstempel werden nachgesehen.

1. `auftraege/_probe/AUF-043_teil1.py` legt die **vier neuen Dateien** an (Schritt 1) → `npx tsc --noEmit`
   und `npx vitest run`, die vollständige Ausgabe **sofort** nach
   `auftraege/_ergebnisse/AUF-043_schritt1.txt`.
2. Erst dann `auftraege/_probe/AUF-043_teil2.py` mit den elf Stücken für `MoreScreen.tsx` (Schritt 2).

**Die Stücke nicht abtippen.** Sie sind lang (bis 224 Zeilen) und stehen in diesem Auftragstext —
`auftraege/AUF-043.md` im Arbeitsort — genau so, wie sie in die Datei gehören. Das Teilskript liest sie
dort, als UTF-8, und macht **vorher jedes `\r\n` zu `\n`**: Im Arbeitsort hat die Datei durch
`core.autocrlf` `\r\n`, die Stücke sind LF-Text. Der Inhalt eines Codeblocks beginnt nach der Zeile mit ```` ```tsx ```` und endet mit dem
Zeilenumbruch vor der schließenden ```` ``` ````. Unter **G1**–**G4** steht je eine neue Datei; unter
**U1**–**U11** zuerst das Suchstück, dann entweder „ersatzlos löschen.“ oder „ersetzen durch:“ mit einem
zweiten Block. Kein Stück trägt den Zusatz „endet ohne Zeilenumbruch“. Vorher prüfen, dass genau 4 bzw.
11 Stücke gelesen wurden, und ihre Längen in Zeilen ins Protokoll schreiben.

**Kein Schritt läuft zweimal.** Jedes Teilskript prüft vor dem Schreiben je Stück: Das Suchstück kommt
**genau einmal** vor, der Ersatz steht **noch nicht** in der Datei, eine neue Datei gibt es noch nicht —
und kein Ersatz und keine neue Datei eines **späteren** Teils ist schon da (sonst lief ein späterer Teil
schon). Sonst Abbruch ohne Schreiben. Es legt vorher Kopien der betroffenen Dateien unter
`auftraege/_probe/AUF-043_vorher/teilN/` ab. Muss ein Schritt doch wiederholt werden: erst von dort
zurückholen, dann neu. **Jede Wiederholung, jede Wiederherstellung und jede nachgestellte Messung gehört
mit Uhrzeit in `nicht_erreicht`.**

**Kein Befehl der Lieferung ruft ein Teilskript auf** — auch keiner, den eine eigene Zwischenabnahme
fährt: Die Abnahme führt jeden Befehl erneut aus.

**Stücke Zeichen für Zeichen übernehmen:** nichts davor oder danach einfügen, auch keine Leerzeile, und
**keine Ersetzung über den Text eines Stücks laufen lassen** außer der einen Umwandlung `\n` → `\r\n`
unten. Hilfsskripte in eigenen Dateien unter `auftraege/_probe/`, nicht in `auftraege/_ergebnisse/`.

**Zeilenenden je Datei feststellen, nicht annehmen:** als **Bytes** lesen; enthält die Datei `\r\n`,
Suchstück und Ersatz **genau einmal** von `\n` nach `\r\n` umwandeln (den LF-Text aus dem Auftrag, nie
einen Text, der schon `\r` enthält), sonst unverändert anwenden. `MoreScreen.tsx` hat heute `\r\n`; die
vier neuen Dateien bekommen `\n`, genau wie im Stück. Vor dem Schreiben prüfen, dass keine Datei `\r\r`
enthält. Codierung UTF-8; außerhalb von ASCII stehen in den Stücken nur `·` (U+00B7), `–` (U+2013), `—` (U+2014), `…` (U+2026) und `✓` (U+2713), die genau so bleiben.

Unter Windows sind `npx` und `npm` `.cmd`-Dateien: im Hilfsskript `npx.cmd`/`npm.cmd` aufrufen oder
`shell=True` setzen.

**Negativkontrollen nur an einer Kopie** des **endgültigen** Stands, nie am Arbeitsstand: `src/`,
`package.json`, `tsconfig.json`, `vite.config.ts` und `capacitor.config.ts` nach
`auftraege/_probe/AUF-043_nk/` kopieren; dort je eine der vier neuen Dateien beiseitelegen, `npx tsc
--noEmit` mit der Kopie als Arbeitsverzeichnis fahren, die Datei zurücklegen. Die NK-Ergebnisdatei
schreibt das NK-Skript **vor** der Lieferung; danach weder die Lieferung noch die Ergebnisdatei neu
schreiben.

```tsx
const FIELDS: { key: keyof Profile; label: string; placeholder: string }[] = [
  { key: 'vorname', label: 'Vorname', placeholder: 'Max' },
  { key: 'nachname', label: 'Nachname', placeholder: 'Mustermann' },

/** Persoenliche Daten fuer den Report-Kopf (aus MoreScreen ausgelagert, AUF-043). */
export function ProfileSection({
  profile,
  save,
}: {
  profile: Profile;
  save: (p: Profile) => Promise<void>;
}) {
  const [form, setForm] = useState<Profile | null>(null);
  const [savedFlash, setSavedFlash] = useState(false);

    setSavedFlash(true);
    setTimeout(() => setSavedFlash(false), 1800);

    <section className="card-section">
      <h2>Persoenliche Daten</h2>

            type="text"
            placeholder={f.placeholder}
            value={current[f.key]}
            onChange={(e) => setField(f.key, e.target.value)}
          />
        </label>
      ))}
      <button className="btn btn-primary" onClick={() => void handleSaveProfile()}>
```

**G3** — `src/ui/components/VacationSection.tsx`: neue Datei, genau so:

```tsx
import { useState } from 'react';
import { differenceInCalendarDays } from 'date-fns';
import {
  dailyTargetMs,
  workdaysInRange,
  type Employment,
  type VacationDay,
} from '../../domain/employment';
import { decimalHours, fromDateInput } from '../../domain/time';
import type { SickPeriod } from '../../domain/sickness';
import { VacationClockodo } from './VacationClockodo';
import { VacationDayRow } from './VacationDayRow';

/**
 * Groesster am Stueck eintragbarer Urlaubszeitraum (Kalendertage). Ein Jahr ist
 * mehr als jeder reale Urlaub; die Grenze verhindert, dass ein Vertipper im
 * Jahresfeld die Vorschau ueber Hunderttausende Tage rechnen laesst.
 */
const MAX_VACATION_RANGE_DAYS = 366;

/**
 * Genommene Urlaubstage: Einzeltag, Zeitraum, Abgleich mit Clockodo und Liste (aus MoreScreen
 * ausgelagert, AUF-043). Die Auswahl "Urlaub fuer Beschaeftigung" bleibt in MoreScreen, weil auch
 * die Krankheitszeiten an ihr haengen.
 */
export function VacationSection({
  employments,
  vacTargetId,
  vacEmp,
  setVacEmpId,
  vacDays,
  addVac,
  addVacMany,
  removeVac,
  refreshVac,
  sickPeriods,
}: {
  employments: readonly Employment[];
  vacTargetId: string;
  vacEmp: Employment | undefined;
  setVacEmpId: (id: string) => void;
  vacDays: readonly VacationDay[];
  addVac: (date: number, note?: string, employmentId?: string) => Promise<void>;
  addVacMany: (dates: readonly number[], employmentId?: string) => Promise<number>;
  removeVac: (date: number, employmentId: string) => Promise<void>;
  refreshVac: () => Promise<void>;
  sickPeriods: readonly SickPeriod[];
}) {
  const [newVacDate, setNewVacDate] = useState('');
  const [vacFrom, setVacFrom] = useState('');
  const [vacTo, setVacTo] = useState('');
  const [vacRangeMsg, setVacRangeMsg] = useState('');

  const empLabel = (id: string) =>
    employments.find((e) => e.id === id)?.name ?? id;

  const handleAddVacation = async () => {
    const t = fromDateInput(newVacDate);
    if (Number.isNaN(t) || !vacTargetId) return;
    await addVac(t, '', vacTargetId);
    setNewVacDate('');
  };

  // Zweiter Erfassungsweg: ganzer Zeitraum statt Einzeltag. Die Vorschau wird
  // bei jeder Eingabe neu berechnet, damit vor dem Klick sichtbar ist, wie
  // viele Tage tatsaechlich eingetragen werden. Die Obergrenze schuetzt den
  // Render-Pfad: ein <input type="date"> laesst Jahreszahlen bis 275760 zu, und
  // workdaysInRange legt pro Kalendertag ein Date-Objekt an.
  const rangeSpanDays =
    Number.isNaN(fromDateInput(vacFrom)) || Number.isNaN(fromDateInput(vacTo))
      ? 0
      : differenceInCalendarDays(fromDateInput(vacTo), fromDateInput(vacFrom)) + 1;
  const rangeTooLong = rangeSpanDays > MAX_VACATION_RANGE_DAYS;
  const rangeDays =
    rangeSpanDays <= 0 || rangeTooLong
      ? []
      : workdaysInRange(
          fromDateInput(vacFrom),
          fromDateInput(vacTo),
          vacEmp ?? { workdaysPerWeek: 5 },
        );

  const handleAddVacationRange = async () => {
    if (rangeDays.length === 0) return;
    const added = await addVacMany(rangeDays, vacTargetId);
    const skipped = rangeDays.length - added;
    setVacFrom('');
    setVacTo('');
    // Inline statt window.alert: die neuen Tage stehen sofort in der Liste
    // darunter, die Meldung ergaenzt nur, was uebersprungen wurde.
    setVacRangeMsg(
      `${added} Urlaubstag(e) eingetragen` +
        (skipped > 0 ? `, ${skipped} war(en) bereits erfasst` : '') +
        '.',
    );
  };

  return (
    <>
      <h3 className="sub-head">Genommene Urlaubstage</h3>
      <p className="muted small">
        Jeder Eintrag zaehlt als 1 Urlaubstag, mindert den Resturlaub des
        jeweiligen Jahres und entlastet das Arbeitszeitkonto um bis zu{' '}
        {vacEmp
          ? decimalHours(dailyTargetMs(vacEmp)).toFixed(2).replace('.', ',')
          : '0,00'}{' '}
        Std. Ist an dem Tag schon Zeit erfasst, wird nur die Differenz
        gutgeschrieben — ein Tag zaehlt nie doppelt.
      </p>
      <label className="field">
        <span>Urlaub fuer Beschaeftigung</span>
        <select
          value={vacTargetId}
          onChange={(e) => setVacEmpId(e.target.value)}
        >
          {employments.map((e) => (
            <option key={e.id} value={e.id}>
              {e.name}
            </option>
          ))}
        </select>
      </label>
      <div className="vac-add">
        <input
          type="date"
          value={newVacDate}
          onChange={(e) => setNewVacDate(e.target.value)}
        />
        <button
          className="btn"
          disabled={!newVacDate}
          onClick={() => void handleAddVacation()}
        >
          Urlaubstag hinzufuegen
        </button>
      </div>

      <p className="muted small vac-or">oder ganzen Zeitraum eintragen:</p>
      <div className="vac-range">
        <label className="field">
          <span>von</span>
          <input
            type="date"
            value={vacFrom}
            onChange={(e) => {
              setVacFrom(e.target.value);
              setVacRangeMsg('');
            }}
          />
        </label>
        <label className="field">
          <span>bis</span>
          <input
            type="date"
            value={vacTo}
            onChange={(e) => {
              setVacTo(e.target.value);
              setVacRangeMsg('');
            }}
          />
        </label>
```

```tsx
 * Daten-Backup: exportieren, importieren (zusammenfuehren oder ersetzen), alle Eintraege als CSV,

export function BackupSection({ employments }: { employments: readonly Employment[] }) {
  const [busy, setBusy] = useState(false);
  const fileRef = useRef<HTMLInputElement>(null);

  const stamp = () => format(Date.now(), 'yyyy-MM-dd_HHmm');

  const exportJson = async () => {

        entriesToCsv(all, employments),
        `Klarzeit-Alle_${stamp()}.csv`,
        'Klarzeit – alle Eintraege',
        'text/csv',
      );
    } catch (e) {
      window.alert(`CSV-Export fehlgeschlagen: ${msg(e)}`);
    } finally {
      setBusy(false);
    }
  };

  const onImportFile = async (e: React.ChangeEvent<HTMLInputElement>) => {
    const file = e.target.files?.[0];
    e.target.value = ''; // erlaubt erneuten Import derselben Datei
    if (!file) return;
    // Standardweg ist das sichere Zusammenfuehren. Das destruktive Ersetzen

      mode = 'replace';

      setBusy(false);

    window.alert('Alle Eintraege geloescht.');

      />
      <button className="btn btn-block danger-outline" disabled={busy} onClick={() => void wipeAll()}>
        Alle Daten loeschen
      </button>
    </section>
  );
}

function msg(e: unknown): string {
```
