# AUF-013 — Kunde, Projekt und Leistung je Eintrag

## Auftrag

Hat die Beschäftigung eines Eintrags einen Clockodo-Zugang, wählt der Nutzer im Eintragsformular
Kunde, Projekt (freiwillig) und Leistung aus den geladenen Clockodo-Listen; die Auswahl wird am
Eintrag gespeichert und reist durch das Backup.

## Warum das gebraucht wird

Clockodo verlangt je Zeiteintrag `customers_id` und `services_id`; `projects_id` ist optional
(Spezifikation `https://docs.clockodo.com/openapi.yaml`, `POST /v2/entries`, `required:
['customers_id', 'time_since', 'time_until', 'services_id']`). Der User will die Leistung je
Eintrag so wählen wie in Clockodo (Screenshot 2026-09-25). Die Vorgaben je Beschäftigung gibt es
seit AUF-012 (`ClockodoConfig.defaultCustomersId` usw.). Übertragen wird hier noch nichts.

## Was zu tun ist

### 1 — Gerüst, dann Tests, dann Ausgangslauf — VOR der Umsetzung

1. In `src/domain/clockodo.ts` den Typ `ClockodoEntryRef` und die Funktionen
   `cleanClockodoEntryRef` und `defaultEntryRef` **nur als Gerüst** ergänzen (Rumpf
   `throw new Error('AUF-013: noch nicht umgesetzt');`). Sonst nichts ändern.
2. Die sechs Tests aus Abschnitt 4 schreiben.
3. `npx vitest run` fahren; `Test Files …`, `Tests …` und die Namen der roten Tests festhalten.
   **Das ist der Ausgangslauf** — er steht in der Lieferung, sonst gilt der Auftrag als nicht

4. Erst danach umsetzen.

### 2 — Datenmodell (`src/domain/clockodo.ts`, `src/domain/types.ts`)

```ts
export interface ClockodoEntryRef {
  customersId: number;
  projectsId: number | null;
  servicesId: number;
}
export function cleanClockodoEntryRef(raw: unknown): ClockodoEntryRef | null;
export function defaultEntryRef(config: ClockodoConfig | null): ClockodoEntryRef | null;
```

- `cleanClockodoEntryRef`: kein Objekt → `null`. `customersId` und `servicesId` müssen positive
  Ganzzahlen sein, sonst ganzer Ref `null`. `projectsId`: fehlt oder `null` → `null`; positive
  Ganzzahl → übernommen; **jeder andere Wert → ganzer Ref `null`** (eine kaputte Projekt-ID darf
  nicht still zu einer Buchung ohne Projekt werden). Die vorhandene Hilfsfunktion `positiveInt`
  benutzen.
- `defaultEntryRef`: `config` ist `null`, oder `defaultCustomersId`/`defaultServicesId` fehlt →
  `null`; sonst `{ customersId, projectsId: defaultProjectsId, servicesId }`.
- `TimeEntry.clockodo?: ClockodoEntryRef | null` mit Kommentar: fehlt/`null` = keine
  Clockodo-Auswahl. `ClockodoEntryRef` per `import type` aus `./clockodo`.

### 3 — Formular, Entwürfe, Backup

**`EntryFormModal.tsx`:**
- `EntryDraft.clockodo: ClockodoEntryRef | null` — **Pflicht im Entwurf**, aus demselben Grund wie
  `breaks` (Dexie-`update` ließe ein fehlendes Feld stehen).
- Abschnitt „Clockodo" **nur**, wenn die gewählte Beschäftigung (`employments`, nach
  `employmentId`) `clockodo !== null` hat. Darin drei Auswahlen aus
  `getClockodoLists(employmentId)`: „Kunde", „Projekt" (nur Projekte dieses Kunden, dazu „kein
  Projekt"), „Leistung". Steht eine gespeicherte ID nicht in der Liste (inzwischen inaktiv),
  bleibt sie als Eintrag `ID <n>` wählbar, statt still zu verschwinden.
- Startwert: `initial.clockodo ?? defaultEntryRef(config)`. Wechselt der Nutzer die
  Beschäftigung, gilt `defaultEntryRef` der neuen. Wechselt er den Kunden, wird das Projekt auf
  „kein Projekt" gesetzt.
- Keine Listen gespeichert → Hinweis
  `Clockodo-Listen fehlen – in Mehr > Beschaeftigung > Verbindung testen.` und die bisherige
  Auswahl bleibt unverändert erhalten.
- Beim Speichern: `clockodo` = Auswahl, wenn Kunde **und** Leistung gewählt sind, sonst `null`;
  ohne Zugang an der Beschäftigung immer `null`. Kein Speicher-Fehler wegen fehlender Auswahl —
  ob ein Eintrag übertragbar ist, entscheidet ein späterer Auftrag.
- Schreibweise der Datei übernehmen (ASCII-Umschrift).

**Entwürfe:** `defaultManualDraft` → `clockodo: null`; `entryToDraft` → `clockodo: entry.clockodo ?? null`;
`openStop` (HomeScreen) → `clockodo: null`.

**`src/db/backup.ts`, `cleanEntry`:** `clockodo` über `cleanClockodoEntryRef`; ungültig oder
fehlend → **Feld fehlt**. Backup-`version` bleibt 3.

- ⛔ **`isValidEntry` in `src/db/backup.ts` nicht anfassen.**
- Nichts an Clockodo senden, kein neuer Client-Aufruf, keine Übertragung, keine Statusanzeige in
  der Eintragsliste — spätere Aufträge.
- `ClockodoSettings.tsx`, `client.ts`, `key-store.ts`, `clockodo-lists.ts` nicht ändern.
- Keine neue Dexie-Version (nicht indiziert); Backup-`version`, `app`-Kennung, DB-Name bleiben.
- Bestehende Tests nicht in ihren Erwartungen ändern. Vergleicht ein bestehender Test ein ganzes
  Objekt, in dem jetzt das neue Feld auftaucht, und muss dafür ergänzt werden: in der Lieferung
  **einzeln nennen, mit Grund**.
- Keine Testing-Library, kein neues Paket, `package.json` nicht ändern, `tools/` nicht anfassen,
  nicht committen.
- Hilfsskripte in reinem Python; keine Fremdprogramme per `subprocess` außer `npx`. Ein
  Kontrollskript prüft die erwartete Rotmenge **selbst** und endet nur dann mit 0, wenn sie stimmt.

> (`main` = `4c3fc3f`): `npx vitest run` → 12 Testdateien, 125 Tests, alle grün;

3. Die 125 bestehenden Tests laufen ohne geänderte Erwartung grün.
4. **NK A (Ganzzahl):** in `cleanClockodoEntryRef` probeweise jede endliche Zahl als ID zulassen →
   `Tests  1 failed | 130 passed`, rot **T2**.
5. **NK B (Leistungspflicht):** `defaultEntryRef` probeweise auch ohne `defaultServicesId` →
   `1 failed | 130 passed`, rot **T3**.
6. **NK C (Backup):** `cleanEntry` probeweise ohne `clockodo` → `1 failed | 130 passed`, rot **T4**.
7. Jede NK wieder heraus; ein letzter Lauf zeigt 131 grün.
8. `git diff --stat` und `git diff --cached --stat` wörtlich; geändert sind genau die Dateien aus

ändern muss, ohne dass es an einem ganzen Objektvergleich liegt — dann verändert die Auswahl mehr
