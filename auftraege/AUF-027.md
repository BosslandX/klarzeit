# AUF-027 — Arbeitstage als Wochentage

## Auftrag

Eine Beschäftigung speichert ihre Arbeitstage als Wochentage (Mo–So), und ein Urlaubszeitraum zählt
nur diese Tage.

## Warum das gebraucht wird

Heute kennt der Vertrag nur die **Anzahl** der Arbeitstage (`workdaysPerWeek`). `workdaysInRange`
zählt deshalb immer Montag bis Freitag, ab sechs Tagen auch den Samstag: Wer Montag bis Donnerstag
arbeitet und eine Urlaubswoche als Zeitraum einträgt, bekommt den freien Freitag als Urlaubstag
gebucht. Die Wochentage sind außerdem die Grundlage für AUF-028 (Feiertage): eine Gutschrift für
einen Feiertag darf nur an einem eigenen Arbeitstag entstehen.

**Entscheidung des Nutzers (2026-11-17):** Plan „Arbeitstage als Wochentage → Feiertage → Vertrag
gültig ab → Krankheit" freigegeben.

**Der Bestand bleibt, wie er ist.** Ohne gewählte Wochentage gilt die bisherige Regel; die App rät
keine Verteilung, die sie nicht kennt (so begründete es schon der Kommentar an `workdaysInRange`).
Das Formular zeigt bei 1 bis 4 Arbeitstagen ohne gespeicherte Wochentage keine Auswahl und bittet
darum. **`workdaysPerWeek` bleibt** und wird aus der Auswahl gesetzt: Es steht in Preferences und
in jedem Backup und trägt Tagessoll und Urlaubsanspruch.

### 0 — Drei getrennte Einspiel-Läufe, in dieser Reihenfolge

**Erst wenn ein Schritt gemessen ist, wird das Skript des nächsten geschrieben.** Die Zeitstempel
werden wieder nachgesehen.

1. `auftraege/_probe/AUF-027_teil1.py` spielt das **Gerüst** (Schritt 1) ein → `npx tsc --noEmit`
   und `npx vitest run` (Gerüstlauf).

   `npx vitest run`, die **vollständige, wörtliche** Ausgabe von vitest (stdout und stderr) nach
   `auftraege/_ergebnisse/AUF-027_ausgangslauf.txt` — **kein Auszug**. Diese Datei danach **nie
   wieder schreiben**.
3. Erst dann `auftraege/_probe/AUF-027_teil3.py` mit der **Umsetzung** (Schritt 3).

Abweichungen gehören in `nicht_erreicht`.

**Jedes Suchstück kommt in seiner Datei genau einmal vor**; das Skript prüft das und bricht sonst ab,
ohne zu schreiben. Mehrere Stücke derselben Datei werden in der angegebenen Reihenfolge nacheinander
angewandt. Die Dateien stehen im Arbeitsort mit **CRLF**: Suchstück und Ersatz mit `\r\n` anwenden,
Zeilenenden wie vorgefunden lassen; die neue Datei mit LF. Codierung UTF-8 — in den Stücken kommen
`—`, `ä` und `§` vor.

**Negativkontrollen nur an einer Kopie**, nie am Arbeitsstand: `src/`, `package.json`,
`vite.config.ts` und `tsconfig.json` nach `auftraege/_probe/AUF-027_nk/` kopieren und dort mutieren und
messen (`npx vitest run` mit diesem Ordner als Arbeitsverzeichnis). Die NK-Ergebnisdatei schreibt das
NK-Skript **vor** der Lieferung; danach weder die Lieferung noch die Ergebnisdatei neu schreiben.

export function cleanWorkWeekdays(raw: unknown): number[] | undefined {
  if (!Array.isArray(raw)) return undefined;
  if (!raw.every((v) => Number.isInteger(v) && v >= 0 && v <= 6)) return undefined;
  const days = [...new Set(raw as number[])].sort((a, b) => a - b);
  return days.length >= 1 && days.length <= WERKTAGE_PER_WEEK ? days : undefined;
}

        </p>
      )}
    </>

}
