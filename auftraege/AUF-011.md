# AUF-011 — Pausen mit Uhrzeit

## Auftrag

Eine Pause wird künftig mit **Beginn und Ende** erfasst statt nur als Minutenzahl; die
Minutensumme `breakMinutes` bleibt gespeichert und wird aus den Pausen berechnet.

## Warum das gebraucht wird

Klarzeit soll Einträge an Clockodo übertragen (Entscheidung des Users, 2026-09-25). Clockodo
kennt laut seiner API-Spezifikation kein Pausenfeld; eine Pause ist dort die Lücke zwischen zwei
Einträgen. Aus „08:00–16:30, 30 min Pause" lässt sich das nicht ehrlich bilden, weil niemand weiß,
wann die Pause war. Erfundene Uhrzeiten in der Zeiterfassung eines Arbeitgebers kommen nicht in
Frage. Dieser Auftrag schafft nur die Daten; die Übertragung selbst ist ein späterer Auftrag.

### 2 — Datenmodell und reine Funktionen

`src/domain/types.ts`:

```ts
/** Eine Pause mit Uhrzeit (epoch ms). */
export interface BreakInterval {
  start: number;
  end: number;
}
```

`TimeEntry` bekommt `breaks?: BreakInterval[]` — **optional**, mit Kommentar: fehlt das Feld,
sind für diesen Eintrag keine Pausenzeiten bekannt (Einträge vor 1.7); dann gilt allein
`breakMinutes`. `breakMinutes` bleibt Pflichtfeld und bleibt die Grundlage von `netMs`, PDF,
CSV und Arbeitszeitkonto.

`src/domain/breaks.ts` (rein, keine Datenbank, keine Oberfläche; Kommentare ohne Umlaute wie im
übrigen Code):

- `breakMinutesOf(breaks: readonly BreakInterval[]): number` — Summe der Pausenlängen in ganzen
  Minuten (`Math.round` über die Summe in ms / `MINUTE` aus `time.ts`).
- `validateBreaks(entry: { start: number; end: number }, breaks: readonly BreakInterval[]): string | null`
  — `null`, wenn gültig, sonst eine Fehlermeldung (ASCII-Umschrift wie im Formular). Geprüft wird,
  in dieser Reihenfolge und **je Regel an genau einer Stelle**:
  1. jede Pause: `end > start` — sonst `'Eine Pause endet nicht nach ihrem Beginn.'`
  2. jede Pause liegt in `[entry.start, entry.end]` — sonst `'Eine Pause liegt ausserhalb von Beginn und Ende.'`
  3. nach Beginn sortiert überschneidet sich keine mit der nächsten — sonst `'Zwei Pausen ueberschneiden sich.'`
  4. Summe der Pausen `<` Dauer des Eintrags — sonst `'Die Pause ist laenger als die erfasste Zeitspanne.'`
  Die Eingabe darf unsortiert sein; die Funktion verändert sie nicht.
- `resolveBreakMinutes(breaks: readonly BreakInterval[], legacyMinutes: number): number` — gibt es
  Pausen mit Uhrzeit, deren Summe (`breakMinutesOf`); sonst `legacyMinutes` unverändert.

### 3 — Formular, Entwürfe, Backup

**`EntryFormModal.tsx`:**
- `EntryDraft` bekommt `breaks: BreakInterval[]` als **Pflichtfeld**. Grund: `updateEntry` nutzt
  Dexies `update`, das nur übergebene Felder ändert. Fehlte `breaks` im Entwurf, bliebe eine im
  Formular entfernte Pause gespeichert. Jeder Entwurf gibt `breaks` deshalb ausdrücklich mit,
  auch leer.
- Das Feld „Pause (Minuten)" entfällt. An seine Stelle tritt eine Liste von Pausen, je Zeile
  „Pause von" und „bis" als `<input type="datetime-local">` (dieselben Helfer
  `toDatetimeLocal`/`fromDatetimeLocal` wie Beginn und Ende) und ein Knopf „Entfernen"; darunter
  „+ Pause". Eine neue Zeile startet **leer** (Wert `NaN`, angezeigt als leeres Feld —
  `toDatetimeLocal(NaN)` würde werfen, also vorher prüfen). **Keine vorbelegten Uhrzeiten.**
- Darunter „Pause gesamt: N min" aus `resolveBreakMinutes`.
- Alter Eintrag (keine `breaks`, aber `breakMinutes > 0`): Hinweiszeile
  `Pause: N min ohne Uhrzeit (aelterer Eintrag).` mit Knopf „Entfernen". Kommt eine Pause mit
  Uhrzeit hinzu, ersetzt sie die alte Minutenangabe (so rechnet `resolveBreakMinutes`).
- Beim Speichern: leere Pausenfelder → Fehler `'Bitte Beginn und Ende jeder Pause angeben.'`;
  dann `validateBreaks`; der Entwurf trägt die Pausen nach Beginn sortiert und
  `breakMinutes = resolveBreakMinutes(pausen, altMinuten)`. Die „Dauer"-Anzeige rechnet damit.
- Schreibweise der umgebenden Texte übernehmen (ASCII-Umschrift, „Taetigkeit").

**Entwürfe:** `defaultManualDraft` (EntriesScreen) → `breaks: []`, `breakMinutes: 0` — die bisherige
Vorgabe von 30 Minuten entfällt, weil sie eine Pause ohne Uhrzeit wäre. `entryToDraft` →
`breaks: entry.breaks ?? []`. `openStop` (HomeScreen) → `breaks: []`.

**`src/db/backup.ts`, `cleanEntry`:** übernimmt `breaks` über eine neue Funktion `cleanBreaks`:
nur Einträge mit endlichen Zahlen `start`, `end` und `end > start`, nach Beginn sortiert; alles
andere fällt still weg. Bleibt nichts übrig, **fehlt das Feld** im Ergebnis. `breakMinutes`
bleibt, wie es im Backup steht. Das Backup-Format bleibt Version 3: eine ältere Klarzeit
verwirft das unbekannte Feld und rechnet mit `breakMinutes` weiter richtig.

## Was ausdrücklich NICHT zu tun ist

  läuft vor der Normalisierung; jede Verschärfung weist ältere Backups ab.
- `entriesToCsv`, `netMs`, `src/domain/aggregate.ts`, `src/domain/employment.ts`,
  `src/pdf/report-pdf.ts` nicht ändern — sie rechnen weiter mit `breakMinutes`.
- Keine neue Dexie-Version (`breaks` wird nicht indiziert), Backup-`version` bleibt 3, Kennung
  `app: 'zeiterfassung'` und DB-Name bleiben.
- Keine Pausen-Taste an der Stoppuhr, keine Clockodo-Anbindung, keine Anzeige der Pausenzeiten in
  Liste, PDF oder CSV — alles spätere Aufträge.
- **Keine vorbelegten oder geschätzten Pausenzeiten**, nirgends.
- Bestehende Tests nicht in ihren Erwartungen ändern. Wo ein bestehender Test einen `EntryDraft`
  baut und nicht mehr kompiliert, bekommt er `breaks: []` — sonst nichts.
- Keine Testing-Library, kein neues Paket, `package.json` nicht ändern. `tools/` nicht anfassen.
  Nicht committen.
- **Hilfsskripte in reinem Python** (`pathlib`, `re`, `subprocess` nur für `npx vitest`/`npx tsc`).
  Keine Fremdprogramme wie `rg` oder `grep` per `subprocess` — die Abnahme läuft in einer Umgebung
  ohne sie (AUF-010: zwei Befunde genau deshalb). Ein Skript, das einen Testlauf fährt, endet mit
  **dessen** Exit-Code; kein erzwungenes `exit 1`.
