# AUF-035 — Geänderte Stoppuhr-Einträge kennzeichnen, Stoppuhr-Zeiten behalten

## Auftrag

Ändert man bei einem Stoppuhr-Eintrag (`source: 'tracked'`) zum ersten Mal Beginn oder Ende, merkt sich
die App die ursprünglichen Zeiten im neuen Feld `trackedTimes`. Weichen die heutigen Zeiten davon ab,
zeigt „Einträge" den Hinweis „geaendert, Stoppuhr 08:00–16:00", das PDF setzt „°" vor die Tätigkeit
(mit Legende), und die CSV nennt die Stoppuhr-Zeiten in der Spalte „Quelle". Das Backup trägt das Feld.

## Warum das gebraucht wird

Punkt 6 des mit dem Nutzer abgestimmten Plans. Bisher markiert das PDF nur nachgetragene Einträge mit
„*"; ein live erfasster und später geänderter Eintrag behält `source: 'tracked'` und sieht im Nachweis aus
wie unverändert.

**Festgelegt (vom Auftraggeber, nicht ändern):**

- Gemerkt wird beim **ersten** Ändern von Beginn oder Ende, nicht bei Tätigkeit, Notiz oder Pausen.
  Spätere Änderungen lassen die gemerkten Zeiten stehen. Nachgetragene Einträge bekommen keine.
- Stehen Beginn und Ende wieder auf den Stoppuhr-Zeiten, gilt der Eintrag als unverändert: kein Hinweis,
  kein Zeichen.
- Das PDF zeigt nur das Zeichen „°" samt Legende, die ursprünglichen Zeiten nennen die App und die CSV.
- Das Feld heißt `trackedTimes` mit `start`/`end` — ein stabiler Bezeichner (Dexie und Backup). Keine neue
  Dexie-Version (kein Index). ⛔ `isValidEntry` nicht anfassen.

## Was zu tun ist

### 0 — Drei getrennte Einspiel-Läufe, in dieser Reihenfolge, jeder genau einmal

**Erst wenn ein Schritt gemessen ist, wird das Skript des nächsten geschrieben** — auch keine Dateien
für einen späteren Schritt vorher anlegen. Die Zeitstempel werden nachgesehen.

1. `auftraege/_probe/AUF-035_teil1.py` spielt das **Gerüst** (Schritt 1) ein → `npx tsc --noEmit` und
   `npx vitest run`, Ausgabe nach `auftraege/_ergebnisse/AUF-035_geruestlauf.txt`.
2. `auftraege/_probe/AUF-035_teil2.py` spielt die **Tests** (Schritt 2) ein → `npx tsc --noEmit` und
   `npx vitest run`, die **vollständige, wörtliche** Ausgabe von vitest (stdout und stderr, als UTF-8)
   **sofort** nach `auftraege/_ergebnisse/AUF-035_ausgangslauf.txt` — **kein Auszug**. Diese Datei danach
   **nie wieder schreiben**.
3. Erst dann `auftraege/_probe/AUF-035_teil3.py` mit der **Umsetzung** (Schritt 3).

**Kein Schritt läuft zweimal — in AUF-034 ist genau das passiert**: Teilschritte liefen erneut, Stücke
wurden doppelt eingefügt, drei Reparaturskripte räumten danach auf, und nichts davon stand in
`nicht_erreicht`. Deshalb:

- Jedes Teilskript prüft vor dem Schreiben je Stück zweierlei: das Suchstück kommt **genau einmal** vor,
  und der Ersatz steht **noch nicht** in der Datei (bei einem leeren Ersatz entfällt die zweite
  Prüfung). Schlägt eine Prüfung fehl, bricht es ab, ohne zu schreiben.
- Jedes Teilskript legt vor dem Schreiben Kopien der betroffenen Dateien unter
  `auftraege/_probe/AUF-035_vorher/teilN/` ab. Muss ein Schritt doch wiederholt werden, werden die
  Dateien zuerst von dort zurückgeholt — und das gehört mit Uhrzeit in `nicht_erreicht`.
- Jede Reparatur nach einem Lauf gehört in `nicht_erreicht`, samt der Frage, ob die Negativkontrollen
  danach am **endgültigen** Stand gefahren wurden. Wenn nicht: neu fahren.

**Jedes Suchstück kommt schon in der Ausgangsdatei seines Schritts genau einmal vor** (vom Auftraggeber
so geprüft). Mehrere Stücke derselben Datei werden in der angegebenen Reihenfolge nacheinander
angewandt.

**Zeilenenden je Datei feststellen, nicht annehmen:** als **Bytes** lesen; enthält die Datei `\r\n`,
Suchstück und Ersatz **genau einmal** von `\n` nach `\r\n` umwandeln (den LF-Text aus dem Auftrag, nie
einen Text, der schon `\r` enthält), sonst unverändert anwenden. Vor dem Schreiben prüfen, dass keine
Datei `\r\r` enthält. Neue Dateien mit LF, jede endet mit einem Zeilenumbruch. Codierung UTF-8; die
Stücke enthalten `°` (U+00B0) und `–` (U+2013), die genau so bleiben.

Unter Windows sind `npx` und `npm` `.cmd`-Dateien: im Hilfsskript `npx.cmd`/`npm.cmd` aufrufen oder
`shell=True` setzen.

**Negativkontrollen nur an einer Kopie** des **endgültigen** Stands, nie am Arbeitsstand: `src/`,
`package.json`, `vite.config.ts` und `tsconfig.json` nach `auftraege/_probe/AUF-035_nk/` kopieren und dort
mutieren und messen (`npx vitest run` mit diesem Ordner als Arbeitsverzeichnis). Die NK-Ergebnisdatei
schreibt das NK-Skript **vor** der Lieferung; danach weder die Lieferung noch die Ergebnisdatei neu
schreiben.

  it('withTrackedTimes: merkt die Stoppuhr-Zeiten bei der ersten Aenderung von Beginn oder Ende', () => {

    expect(withTrackedTimes({ ...stoppuhr, source: 'manual' }, { start: tag + 7 * H })).toEqual({
      start: tag + 7 * H,
    });

export function cleanTrackedTimes(raw: unknown): TrackedTimes | undefined {
  if (typeof raw !== 'object' || raw === null) return undefined;
  const x = raw as Record<string, unknown>;
  const { start, end } = x;
  if (typeof start !== 'number' || !Number.isFinite(start)) return undefined;
  if (typeof end !== 'number' || !Number.isFinite(end) || end <= start) return undefined;
  return { start, end };
}
